# AGENTS.md

Instructions for agents (Claude Code, Codex, etc.) working in this repository.

## Purpose

A satellite repository of Claude Code mods — function hooks plugins in TypeScript. It **complements** the plugins and mods the user already has installed rather than replacing them: mods from here are attached as additional plugin folders (`CLAUDE_CODE_PLUGIN_DIRS`) next to the installed ones (`enabledPlugins`, marketplaces, `~/.claude/skills`).

## Stack and environment

- Node 24 and pnpm 11 are pinned in `mise.toml`; local variables go in `mise.local.toml` (in .gitignore, sample in `mise.local.toml.example`).
- pnpm workspace: `plugins/*`, shared tool versions via `catalog:` in `pnpm-workspace.yaml`. Install new dev dependencies at the root through the catalog, not in mods.
- TypeScript 7 (type checking only, no build — the engine runs `.ts/.tsx` itself), Biome for linting and formatting.
- Scripts in `scripts/*.mjs` are plain Node with no dependencies and are cross-platform (the main OS is Windows).

## Mod structure

```
plugins/<mod>/
  .claude-plugin/plugin.json   name (= folder and package name), version, description, author[, types]
  hooks/hooks.json             { "modules": ["./register.tsx"] } — a single path
  hooks/register.tsx           export const register: Register = (on, options) => { ... }
  hooks/*.ts                   pure logic without `$`, imported from register
  hooks/*.test.ts              tests: import { test, expect, mock } from 'claude-code/testing'
  types/index.d.ts             $.state contract (interface PluginState) — only if the mod keeps state
  package.json                 check/test/typecheck/validate scripts, no dependencies
  tsconfig.json                extends ../../tsconfig.base.json + include ../../types/engine
  README.md                    purpose and the marketplace install line
```

Create a new mod only via `pnpm new <mod> "description"` (template `templates/mod`). The script refuses if the name is taken by an installed plugin.

## Runtime constraints

- The module runs in a sandbox: **no Node, no DOM**; everything external goes through `$` (`$.fs`, `$.process`, `$.clock`, `$.store`, `$.ui`, ...).
- Import only files **inside the plugin folder**, with a static `import`. `import()` breaks loading. npm packages are unavailable at runtime.
- Shared code between mods at runtime goes through the plugin contract (`dependencies` in plugin.json + a noun in `engine.create`), not through a relative import from a neighboring folder.
- JSX is compiled against the global `h`; elements come from `$.ui.resolve(e)`, not from globals.
- State for rendering is `$.state` (survives hot reload); across sessions use `$.store`. Module variables are reset on every reload.

## Coexistence with installed plugins

- Mod hooks run in the same chain as the hooks of installed plugins. If a hook does not respond itself, it must call `next(e)`, otherwise it will silence other plugins and the engine's behavior.
- Other plugins also render on shared components for `ui.render` (`AbovePrompt`, `UserMessage`, `ToolUse`...): intercept only with an exact matcher (`requestId`, `props`), and return `next(e)` in all other cases.
- Names of mods, slash commands, and `$.tool.register` must not coincide with installed ones: `pnpm dev:status` shows what is loaded besides the repository and any name conflicts.
- Equip guard hooks (`tool.call`, `prompt.submit`, ...) with `.catch(($, e, next) => next.called ? next(e) : { deny: '...' })`.
- Do not edit `enabledPlugins`, `extraKnownMarketplaces`, `pluginConfigs`, or other people's plugins. `dev:link*` changes only `CLAUDE_CODE_PLUGIN_DIRS`/`CLAUDE_CODE_PLUGIN_DIR_WATCH` and preserves other entries.
- `pnpm dev:link:desktop` edits the global `~/.claude/settings.json`: run it only with the user's explicit consent.

## Types and API reference

- The authoritative source is `types/engine/claude-code/index.d.ts` (~15k lines): grep for an event or method name (`'tool.call'`, `Pane: {`, `export type ToolCallResult`), then read the declaration and its doc comment with an example.
- `types/engine/` is a local copy of the engine declarations, generated by `pnpm types:sync` and not committed (it is in .gitignore): run it after cloning and after updating Claude Code.
- `plugins/*/.claude-plugin/types/` is placed by the engine itself when it loads a mod: it is in .gitignore, do not edit it.
- In tests, `$.command.run` is typed with the full `CommandRunInput` (`origin` and `presentation` are required).

## Commands

| Command | What it does |
| --- | --- |
| `pnpm install` | install (after `mise install`) |
| `pnpm new <mod> "description"` | scaffold a mod, update the marketplace, relink |
| `pnpm check [mod...]` | `claude plugin validate` + `tsc -p` + `claude plugin test` + name-conflict check |
| `pnpm --filter <mod> check` | the same for a single mod via the workspace |
| `pnpm watch [mod...]` | typecheck and tests on every save |
| `pnpm lint` / `pnpm format` | Biome |
| `pnpm dev:link` | mods → `mise.local.toml` (for `claude` run from a terminal in the repository) |
| `pnpm dev:link:desktop` | mods → env in `~/.claude/settings.json` (all new Claude Desktop sessions, hot reload) |
| `pnpm dev:status` | what is loaded besides the repository, what is connected, conflicts |
| `pnpm marketplace` | rebuild `.claude-plugin/marketplace.json` |
| `pnpm types:sync` | update `types/engine` |

## Workflow

1. Logic goes into pure functions + `*.test.ts`; hooks in `register.tsx` stay thin.
2. Run `pnpm check <mod>` until green; in the validate output, look at what is hooked, the gating hooks, and state reads and writes.
3. `pnpm lint` with no errors.
4. Live check — in a session with the mods connected: saving reloads the mod after a turn. Load and hook errors appear as a dim line in the transcript; in full, in `claude --debug`.
5. Before releasing a mod: bump `version` in plugin.json, run `pnpm marketplace`, commit and push to `gidragir/claude-mods`, then tag `vX.Y.Z` and publish with `gh release create` (the repo is public and is the marketplace: users install with `/plugin marketplace add gidragir/claude-mods`, then `/plugin install <mod>@claude-mods`).

## Conventions

- Code, identifiers, comments, README files, and user-facing messages are all in English.
- Formatting — Biome (single quotes, no semicolons, width 140); do not argue with the formatter.
- Commits — only when the user asks.
